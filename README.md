# Secure File Storage Management System Using Data Management and Security Tools

### Client Enterprise: Sri Vishnu Heat Treaters
**Tagline**: *Secure. Manage. Protect.*

---

## 1. Project Overview

The **Secure File Storage Management System** is an enterprise-grade document security and metallurgical records repository engineered specifically for **Sri Vishnu Heat Treaters**. 

The system protects sensitive industrial documents—including gas carburizing heat-treatment cycles, pyrometry surveys (CQI-9), tensile/hardness inspection test certificates (EN 10204 3.1), customer engineering CAD specifications, and IATF 16949 audit records.

---

## 2. Technology Stack & Security Architecture

### Frontend
- **Framework**: React 19 + TypeScript (Vite bundler)
- **Styling**: Tailwind CSS with industrial enterprise dark/navy palette
- **Data Visualizations**: Chart.js / interactive SVG breakdowns
- **Icons**: Lucide React & Font Awesome

### Backend (Python Flask REST API)
- **Runtime**: Python 3.10+
- **Framework**: Flask, Flask-CORS
- **Session Security**: Flask-JWT-Extended (signed HS256 JWT tokens)
- **Database ORM**: Flask-SQLAlchemy, PyMySQL (MySQL 8.0) & SQLite3
- **Password Security**: bcrypt (12 rounds cost factor, salted)
- **Multi-Factor Auth**: PyOTP (RFC 6238 Time-based One-Time Password / TOTP)
- **File Encryption**: `cryptography` library (AES-256-GCM with 96-bit IV and 128-bit authentication tag)
- **File Integrity**: SHA-256 cryptographic digests verified against original tamper signatures

## 4. Local Installation & Setup Guide

### Step 1: Install Python & Node.js
Ensure you have Python 3.10+ and Node.js 18+ installed on your operating system:
```bash
python3 --version
node --version
```

### Step 2: Set Up Virtual Environment
```bash
# Clone the repository
git clone https://github.com/srivishnu-heattreaters/secure-file-vault.git
cd secure-file-vault

# Create virtual environment
python3 -m venv venv

# Activate virtual environment
# On Linux/macOS:
source venv/bin/activate
# On Windows:
venv\Scripts\activate
```

### Step 3: Install Backend Dependencies
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### Step 4: Configure Database
Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```
For production MySQL:
```bash
mysql -u root -p < database/schema.sql
```
For local testing, SQLite is supported out of the box with zero external configuration required.

### Step 5: Start the Python Flask Backend
```bash
python backend/app.py
# Backend starts on http://localhost:5000 with CORS enabled
```

### Step 6: Start the Frontend Application
In a separate terminal:
```bash
npm install
npm run dev
# Frontend runs on http://localhost:3000
```

## 6. Testing & Demonstration Workflows (For Project Viva)

1. **Testing Authentication & Brute-Force Lockout**:
   - On the login screen, enter invalid credentials 3 times or click **"Test Failed Password"**.
   - Observe immediate account lockout, IP address logging (`182.72.194.50`), and generation of a High-Severity security alert.
   - Use the **Admin Unlock** action to restore access.

2. **Testing Two-Factor Authentication (OTP)**:
   - Sign in as `admin`. The system requests the 6-digit TOTP token.
   - Click **"Auto-Fill OTP"** to enter the live 30-second token generated by the simulated PyOTP engine.
   - Verify JWT session issuance and automated RBAC policy loading.

3. **Testing AES-256-GCM Encryption**:
   - Upload any `.pdf` or `.docx` document.
   - View document details: notice the generated 96-bit Initialization Vector (IV), 128-bit Authentication Tag, and encrypted ciphertext hex preview.
   - Download the file: the system temporarily decrypts the byte stream in memory before browser file delivery.

4. **Testing File Integrity & Tamper Detection**:
   - Navigate to **"File Integrity (SHA-256)"**.
   - Click **"Verify Integrity"** to see a 100% hash match against the blockchain/immutable signature.
   - Click **"Simulate Tamper"** to alter a byte in the encrypted ciphertext.
   - The integrity engine flags the document as **Tampered (Hash Mismatch)** and triggers a critical Security Center alert.

5. **Testing Document Approval Workflow**:
   - As `suresh_op`, upload a sensitive metallurgical record (e.g. *Batch_Record_SQF_4412.pdf*).
   - Sign in as `karthik_qa` (Manager) and navigate to **"Approvals"**.
   - Inspect the heat cycle parameters, enter approval remarks, and click **"Approve"**.
